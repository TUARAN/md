# 创作名片 · 链接与数据说明

创作名片的**主页链接**、**粉丝量**、**阅读量**来自不同层，不要混为一谈。实现均在 `apps/web/src/utils/socialAccounts.ts`，Pinia 存于 `useSocialAccountsStore`。

---

## 工作流中的平台矩阵

内容同步成稿后，在工作流 **平台矩阵** 步骤按创作者 ID（默认 `tuaran`）查看各渠道粉丝/阅读。

| 来源             | 说明                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------ |
| **COSE 检测**    | 常规路径：扩展登录后「重新检测账号」，写入浏览器缓存，**优先于**下表快照                   |
| **仓库静态快照** | 扩展无数据时使用；部分云社区等难以抓全量统计或稳定主页，需**手动改代码**维护               |
| **Fork + PR**    | 默认仅维护安东尼（`tuaran`）；其他创作者可改 `socialAccounts.ts` / `creatorOffer/` 后提 PR |

## 数据来源总览（先看这个）

名片上每个平台卡片展示三类信息：**主页 URL**、**粉丝量**、**阅读量**。来源与优先级如下。

| 层级                 | 是什么                                                           | 何时写入                               | 优先级                               | 典型表现                                                                              |
| -------------------- | ---------------------------------------------------------------- | -------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------- |
| **① 扩展实时检测**   | COSE 在你**已登录**的浏览器里读到的账号字段                      | 编辑器页加载、点「重新检测账号」       | **最高**（粉丝/阅读）                | 扩展若返回 `followers` / `reads` 等，直接展示                                         |
| **② 浏览器本地缓存** | 把 ① 的结果存进 `localStorage`                                   | 每次检测成功后 `cacheFromPostAccounts` | 介于 ① 与 ③ 之间                     | 键名带项目 prefix：`creator-social-accounts`、`creator-profile`；**不是**服务端数据库 |
| **③ 仓库静态快照**   | `PLATFORM_DEFAULT_PROFILE_STATS`（TUARAN 人工维护）              | 改代码发版；刷新名片时合并进展示       | **仅当 ①② 没有该字段时** 补粉丝/阅读 | 掘金/知乎/头条/小红书为校对值；其余 10 平台为「粉丝 100、阅读 2 万」预估              |
| **④ 仓库默认主页**   | `PLATFORM_DEFAULT_PROFILE_URLS`（只负责 **URL**，不含粉丝/阅读） | 同上                                   | 用于链接，与粉丝/阅读无关            | 扩展/缓存拿不到个人主页时用 TUARAN 各站主页                                           |
| **⑤ 未命中**         | —                                                                | —                                      | —                                    | 名片显示 **「未缓存」**                                                               |

**重要：**

- **没有**本站后台定时爬各平台；也**没有**用你账号密码去服务器登录抓数。
- **快照 ≠ 缓存**：快照在 **Git 代码里**，全用户看到的是同一套 TUARAN 默认值；缓存在 **本机浏览器**，来自你这台机器上扩展最近一次检测。
- **全平台合计「约 3.1 万粉丝 / 约 504 万阅读」** 是把当前展示用的数字（含 ③ 预估）简单相加，**不是**各平台官方统一口径，不能当真实财报；**创作名片转化漏斗中的「曝光示意」不等于该阅读加总**。

### 展示时实际怎么合并（粉丝 / 阅读）

```
最终粉丝 = 扩展/缓存里的 followers  ??  PLATFORM_DEFAULT_PROFILE_STATS[type].followers  ??  「未缓存」
最终阅读 = 扩展/缓存里的 reads       ??  PLATFORM_DEFAULT_PROFILE_STATS[type].reads       ??  「未缓存」
```

（`??` 表示：前面有值就用前面的，否则用后面的。）

### 主页 URL 单独一套优先级

与粉丝/阅读无关，见下文「解析顺序」：扩展主页字段 → uid 拼链 → 默认主页表 → 平台门户。

### 分享链接

带 `?profile=` 的 URL 是**当时编码进链接的一份名片快照**（含各平台字段），打开优先用 URL 里的数据，而不是重新爬站。

## 平台主页链接规则

## 适用范围（无歧义）

`PLATFORM_DEFAULT_PROFILE_URLS` 表里的链接是 **创作者 ID `TUARAN` 在各平台的个人主页**，由仓库维护方写死，用作：

- 扩展/缓存解析不出 TUARAN 的真实主页时的兜底；
- 名片上补全「该平台应有展示项」时的固定跳转。

**不是**「按平台类型的通用首页」，也**不是**其他博主 fork 后应沿用的默认值。其他创作者需改表或走扩展检测到的 uid 拼链。

## 解析顺序

对单个已登录账号，按以下顺序决定名片上的 `url`：

1. 扩展返回的明确主页字段（`profileUrl` / `profile` / `homepage`），且不是编辑/发布页
2. 用有效 `uid` 按平台规则拼接个人主页（见 `PLATFORM_PROFILE_URL_BUILDERS`）
3. 扩展的 `home` / `url`，仅当判断为个人主页而非编辑页时采用
4. 从编辑页 URL 中解析出用户名后再拼接主页
5. **`PLATFORM_DEFAULT_PROFILE_URLS`**：本站维护的默认主页（扩展/缓存拿不到时）
6. **`PLATFORM_HOME_URLS`**：平台门户首页（无默认配置时的最后兜底）

## 浏览器本地缓存说明（②）

| 项目       | 说明                                                                                 |
| ---------- | ------------------------------------------------------------------------------------ |
| 存哪       | 浏览器 `localStorage`（键名带项目 `prefix`）                                         |
| 存什么     | 最近一次扩展检测得到的账号列表：登录态、uid、主页 url、**若有则**粉丝/阅读等         |
| 何时更新   | 打开编辑器相关页自动检测、创作名片点「重新检测账号」                                 |
| 与快照关系 | 检测到的字段覆盖快照；检测不到时回落到 ③                                             |
| 清缓存     | 浏览器清除本站数据即可；改代码里的默认表后**不必**清缓存，刷新名片会重算链接并补快照 |

## 与 COSE 的关系（①）

| 扩展负责                                                                       | 扩展不负责                                              |
| ------------------------------------------------------------------------------ | ------------------------------------------------------- |
| 各平台是否已登录、原始 `home` / `url` / uid、**部分平台**可能带的粉丝/阅读字段 | 替你在云端登录、定时爬全站、保证数字与官方 App 完全一致 |
| 把结果交给本站 `normalizePublicSocialAccounts` 写入 ②                          | 自动维护 ③ 快照表（快照仍须改代码或你提供数据）         |

**名片上的主页链接**一律再经 `resolveSocialAccountUrl` 处理，避免把同步用的编辑页当成个人主页。
