# 网站设计与交互总结

日期：2026-05-13

文件名：`ai-context/2026-05-13-site-design-interaction-summary.md`

## 背景

本总结基于当前本地项目 `/Users/tuaran/Documents/GitHub/md` 的代码结构、运行状态，以及对核心页面和组件的走查。项目当前从 `doocs/md` 的 Markdown 编辑器能力演化为面向内容运营的“内容工厂”工具。

## 整体设计

网站底层能力仍然是 Markdown 编辑、实时预览、样式配置、图片上传、富文本复制和多平台内容同步。上层产品叙事被包装成一条内容运营流程：

```text
数据获取 -> 风格二创 -> 内容同步 -> 宣发活跃 -> 闭环汇报
```

当前真正完整可用的核心是“内容同步”：左侧编辑、右侧预览、复制富文本、样式配置、文件/插入/格式菜单。数据获取页接入了 GNews、NewsAPI 等资讯源；风格二创页目前主要是提示词模板；宣发活跃和闭环汇报目前是占位。

整体定位偏专业工具型，信息密度高，适合熟悉 Markdown、多平台发布和内容运营流程的用户。对新用户来说，上手成本偏高。

## 交互结构

顶部是工作流导航，用户可以在五个阶段之间切换：

- 数据获取
- 风格二创
- 内容同步
- 宣发活跃
- 闭环汇报

内容同步页是主工作台，支持可拖拽分栏：

- 文章列表
- 文件夹来源面板
- Markdown 编辑器
- 预览区
- CSS 编辑器
- 样式面板

数据获取页采用“检索配置 + 结果预览/源码 + 去风格二创”的模式。AI 对话、图片上传、模板、导入、公众号发布等能力主要通过弹窗、菜单或侧边配置进入。

整体交互是强工具台风格，功能入口丰富，但同时也导致路径较多、层级较深。

## 主要问题

### 1. 产品承诺大于当前可用能力

顶部文案和 README 强调“30 分钟完成 30+平台同步”“全链路内容运营工作流”，但目前完整闭环主要还是编辑、排版、复制。宣发活跃、闭环汇报还只是占位，用户预期容易被拉高，实际体验会产生落差。

### 2. 工作流导航看起来完整，但实际功能深浅不一

五步流程在视觉上处于同一层级，但成熟度差异很大：

- 内容同步：最完整
- 数据获取：半完整
- 风格二创：偏模板库
- 宣发活跃：占位
- 闭环汇报：占位

用户点击顶部流程时，会以为这是完整主流程，但实际体验更像产品路线图。

### 3. 数据获取失败反馈不够可操作

GNews 在本地和线上都可能出现 `Failed to fetch`。真实原因可能包括：

- API Key 缺失或无效
- 前端没有走代理
- Worker CORS 配置不匹配
- Worker secret 未配置
- `workers.dev` 网络不可达或超时
- GNews 上游接口失败

如果界面只显示原始错误，用户无法判断下一步应该填 key、配置代理、检查 Worker，还是换网络。

### 4. 信息架构有混合感

同一个页面里同时存在：

- 工作流导航
- Markdown 编辑器菜单
- AI 弹窗
- 样式面板
- CSS 编辑器
- 文件/文章侧栏

对老用户来说能力很强，对新用户来说会分不清当前任务到底是写文章、找资讯、做 AI 改写，还是准备发布。

### 5. 风格二创没有真正接住数据获取

数据获取结果可以“去风格二创”，但风格二创页本身更像提示词模板库。理想状态下，这一步应该直接承接：

- 已获取的资讯
- 当前正文
- 目标平台
- 语气风格
- 字数与结构要求

然后生成多个平台版本，而不是只提供可复制的提示词模板。

### 6. 多平台同步的核心动作还不够显性

“复制”是关键动作，但“复制到哪里、复制后如何验证、不同平台差异怎么处理”没有形成清晰流程。对用户来说，多平台同步不是一个按钮，而是一套可重复执行的发布检查流。

### 7. 顶部品牌文案和工具界面略冲突

工具本体是高密度生产台，右上角动态艺术字偏品牌展示。它有记忆点，但在专业编辑器里可能抢注意力，尤其当用户长时间编辑时。

## 我的思考

这个产品最有价值的方向不是继续堆入口，而是把“从素材到发布”的主路径做顺。当前应该优先收束成三个确定场景：

1. 找素材：关键词检索、来源过滤、结果整理、错误诊断清楚。
2. 写成稿：把素材送进 AI 或编辑器，保留事实来源，生成可编辑 Markdown。
3. 发出去：复制/同步到目标平台，并给出平台适配检查。

相比继续强化“五步全链路”的外壳，现阶段更应该把一条主链路打磨到稳定、可解释、可重复。

## 建议调整方向

### 1. 默认主任务明确为“写一篇并发布”

不要让用户一进入就面对完整五步愿景。默认路径可以更收敛：

```text
找素材 -> 生成/编辑正文 -> 复制发布
```

其他能力可以作为高级功能或后续扩展。

### 2. 对占位步骤降级展示

宣发活跃、闭环汇报目前应该标记为“即将接入”或放入路线图区域，避免和已完成能力同权重。

### 3. 数据获取页增加环境诊断

建议在数据获取页展示或内置诊断：

- 当前是否启用代理
- 当前使用的是哪个信息源
- 是否检测到 API Key
- 请求目标是直连 GNews 还是 Worker
- CORS/超时/key 错误分别给出不同提示

这样用户看到失败时能知道要改哪里。

### 4. 风格二创升级为真正的工作台

从“提示词模板列表”升级为：

- 输入材料区
- 目标平台选择
- 风格选择
- 生成结果区
- 一键送入编辑器

这样才能真正承接数据获取结果。

### 5. 内容同步页强化发布流程

将“复制”扩展为更明确的发布流程：

- 复制富文本
- 打开目标平台
- 检查图片
- 检查链接
- 检查排版
- 标记发布状态

这比单纯强调“30+平台同步”更可信。

### 6. 降低主界面的同时可见复杂度

保留主按钮：

- 获取
- 生成
- 编辑
- 复制
- 发布

低频能力收进“更多”或高级设置。专业能力仍然保留，但不要让新用户第一眼被所有配置淹没。

## 总结

这个网站的底层编辑器能力比较扎实，适合继续作为内容生产工具演进。当前最大问题不是 UI 不够漂亮，而是产品叙事和真实能力之间还没有完全对齐。

短期最值得做的是：把“找素材 -> 二创成稿 -> 编辑排版 -> 复制发布”这条主链路做稳定、做清楚、做可诊断。等这条链路跑顺，再扩展宣发活跃和闭环汇报，会比现在直接展示完整五步工作流更稳。
